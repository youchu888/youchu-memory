# TG/bus 长消息禁止砍尾，必须分片续发

## 背景

bus#8010 狂人指出又初 bus#8008 末尾像被截断（选项号段）；主人同步发现 TG 私聊长消息也不全。根因是出站路径多处 `text[:4096]` / `text[:3500]` 静默砍尾，而 `split_message` 只在少数路径用了。

## 坑 / 错误做法

- `_send_chat_message`：`text[:4096]` 直接砍
- `agent_bus_send._mirror_outbound_tg` / `emit_reply`：`text[:3500]` 入库再镜像
- `agent_bus_tg_mirror._notify_status`：整段一次 `send_message`，超长失败或砍尾
- `extract_bus_reply`：回狂人正文 `[:3500]`

## 正确做法

1. 统一用 `omdb/tgbot/tg_text_split.py`：`split_message` / `split_message_numbered`
2. Bot 出站（`_send_chat_message`）与 status_mirror（`_notify_status`）超长**分多条续发**，禁止 `[:N]`
3. bus 发送：`agent_bus_send.py` 超长自动分片；长文用 `--text-file`，避免 shell/工具参数截断
4. 截断被对方指出 → **立刻补发缺段全文**再结案（见 2026-08-06 lesson）

## 验证

- `python -c` 导入 `tg_text_split` + `bot.split_message` 对超长串返回多段且不丢字
- `bash omdb/tgbot/restart.sh` 后 mirror 日志无 Traceback
- bus#8011 含完整 D1–D5 选项号

## 关联

- 脚本：`omdb/tgbot/tg_text_split.py`、`bot.py`、`agent_bus_tg_mirror.py`、`tg_task_tracker.py`
- 发送：`.claude/database/scripts/notify/agent_bus_send.py`
- 先例：`2026-08-06-bus-转发须自检正文完整-截断导致对方看不到问题时立即补发全量说明再结案.md`
