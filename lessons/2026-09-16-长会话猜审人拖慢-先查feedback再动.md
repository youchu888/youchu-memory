# 长会话猜审人拖慢：先查 feedback 再动

## 背景

归因 1.0.11 发产提审时，连续试 `yehua` / `野花` / `mudan99` / `kakakh72`，又误提蓝猫，再改野花；同会话还叠漏斗、文档清理、占位表解释，体感越来越慢。

## 坑 / 错误做法

- 提审前不读 `feedback_reviewer_usernames.md`，靠猜邮箱/拼音
- 猜错后继续扫 openapi / users，多轮试错
- 多主题挤在同一长会话，上下文膨胀后每步都慢
- 概念题（占位 SQL 干什么）展开过长，像在写说明书

## 正确做法

1. 提审：直接读 `~/.dc-platform/memory/feedback_reviewer_usernames.md` → `野花` = `kakakh7787@gmail.com`，一次 POST
2. 发产通知：一句状态 + 可转发文案，不重跑整包探活
3. 归因 / 漏斗 / 文档清理 **做完就新开对话**（`agent-speed` 一任务一会话）
4. 解释题：先给结论（占坑空跑 / 别删），表一行即可

## 验证

下次 `request-publish` 不出现「用户不存在」试错链；审人邮箱与 feedback 表一致。
