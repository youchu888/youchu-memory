# 开发平台审核：同线快照 / 中间步探针（S3 规则缺口）

## 背景

工作狂人群消息（2026-11-17，@anna_cute9）：提审被拒。先报「只认同线快照在前、不认跨线探针」；随后根因定位到发布审核 **S3 闸** 的依赖覆盖检查。属审核规则漏洞，非开发写法问题；拟修待知秋确认后上线。

## 坑 / 错误做法

- 把 S3 依赖覆盖拒审当成步骤 SQL/挂法写错，从 S1 重来或为此重跑数据。
- 以为调度器不支持中间步探针（运行时其实已支持；拦的是审核闸）。

## 正确做法

- **S3 依赖覆盖（现状缺口）**：只扫同线前序步产出 + **该线第一步**探针，**不认**中间步自己配的探针 → 中间步挂探针会被误拦。
- **拟修方向**（待知秋确认）：审核同时认 **本步** 与 **同线前序步** 所配探针。
- 规则修好上线后：在**原** dev-session 重新提交即可；不必从 S1 重来，不必重跑数据；等群里 @ 再提，勿提前重提。
- 同槽跨线先后以步骤级 runlog/探针声明为准（见 pipeline-runner `Probe.scala`），不能单靠同线快照排序。

## 验证

- 中间步自配探针的会话，S3 依赖覆盖不再误拒。
- 原 session 重提可通过，且无需重跑数据。
