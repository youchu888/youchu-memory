# 狂人 bus 秒回执可短，后面必须追加「实际做了什么」

## 背景

bus#8437 快车道秒回「已知悉」结案，主人看不出干了啥。随后补 SQL 仍偏材料堆砌。主人定：秒回执保持原样，后面再追加一条把实际动作写清楚。

## 坑 / 错误做法

- 秒回执当结案：`[REPLY] bus#N 收到，已知悉。`
- 结案回执只贴材料、不写「我做了哪几步」
- 看到「别动 / HOLD / 验收通过」就整封只回不干

## 正确做法

1. **秒回执保持原样**：60s 内 ACK 一行，不结案
2. **干活**
3. **追加一条结案回执**，必须能当工作记录读：
   - 动没动文件 / 覆盖没覆盖生产
   - 查了哪套环境、哪个 wf/task/版本
   - 核了哪几条、结论是什么
   - 材料贴在哪条出站（SQL 全文另条可以，但本条要写清做了什么）
4. 正文有「贴 bus / 要核 / 请确认」→ `work`，即使夹带 HOLD、别动

## 验证

- 同一主线能看到：短 ACK + 一条「1. 2. 3. 实际做了什么」
- 只看结案回执，不翻聊天也能知道干了啥
