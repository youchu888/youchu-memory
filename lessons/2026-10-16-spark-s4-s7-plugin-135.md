# Spark 任务测试与生产发布走开发平台插件 0.0.135

## 背景

2026-10-16 定案：海豚上还没迁的任务改迁到 Spark 和调度器。测试和生产都在开发平台会话里点完，插件版本 0.0.135。不走 ssh、不登录 hadoop、不自己写 SR。

## 坑 / 错误做法

- 用手搓调度接口、yarn 或海豚代替平台阶段。
- 提交还在本地、没有推到远端就点部署。
- 生产环境删表重建，或结构不一致时自己改表。
- 生产探针用水位以外的规则。
- 普通开发账号自己发生产。

## 正确做法

插件登录后，全程在会话里按顺序点。

测试五步，前一步过了才解锁下一步：

1. 提交代码并推到远端。平台按这次提交把 SQL 部署到测试调度器。远端没有这次提交就拒绝。
2. 建表。Paimon 和 SR 的建表文件先做静态检查和调度器预演，再执行。Paimon 结构变了就删表重建。SR 只建不删，结构变了给出删表语句，交给运维。
3. 挂调度。按设计阶段写好的线、槽位、放行钩子挂进测试编排，挂完自动做初始化。
4. 跑一步。选一天；小时任务再选一个小时。用来证明能出数，跑完自动删掉这次写入。
5. 定起点补数。选定的那天就是测试环境的历史起点，补到最近一格，之后调度器自己接着跑。

通过标准：每步成功，而且写出 Paimon 表的那一步行数大于 0。代码重新推送后，建表、单跑、补数三步要重做。

生产五步，把测试挂好的原样搬过去：

1. 确认。列出测试的槽位、分组、排在哪一步后面，对照生产编排，只看不改。
2. 建表。Paimon 看过脚本后点确认建表。生产只建不删；表已在且结构不同，只报差异。SR 建表语句交给运维，建好再勾上。
3. 部署。把已推送的那版 SQL 送到生产调度器，并挂进生产编排。生产没有对应分组时停下，先同步编排。
4. 补数。从历史起点逐格补到最近一格，之后调度器自己接着跑。
5. 完成。登记发布。服务端回读生产编排确认后才算完成。

权限：开发平台账号；`dmp/dc-parent` 仓库的推送权限。生产发布要管理员，或本会话指定的审核人且申请仍在待审。SR 建表不需要自己的写库权限。不需要 hadoop 的 ssh，也不需要 VPN。

限制：生产探针只用水位规则。新建一条线谁批还没定，遇到先问清楚再挂。

## 验证

插件版本是 0.0.135。测试五步都成功，产出表行数大于 0。生产登记后，编排里能看到该步，且和测试的槽位、顺序一致。
