# Spark 提审前先问狂人；禁直接 request-publish

## 背景

bus#14641 又初把 7 个 Spark 迁移会话直接 RP→野花；狂人 #14642 全部压住并令撤回。

## 坑 / 错误做法

- 未先问能不能提就 `request-publish`，再让狂人把关
- 已定「等 bitmap 字典整体重做 / 已撤本周产升」的表（渠道日指标、部门/产品推广周月）仍提审
- 与整份编排大版本（如 v145）同窗口抢发，易 409 或冲掉待生效改动

## 正确做法

1. **提审前先 bus 问狂人能不能提**；得到可提日/范围后再 `request-publish`
2. bitmap 暂停清单（渠道日指标 013、部门周/月 001/002、产品周 003、产品月 002）：口径未变前不提审、不改 SQL/编排/生产表；产品月不用找野花回退
3. 渠道汇总 014、归因看板 006、无候选 007：等大版本（v145）发完并观察稳定 → 整理影子全键比对 + 连续对平天数 → 狂人审过再定发日
4. 平台无「狂人」账号时：审核人可暂指定野花，但**仍须先过狂人可提闸**；野花侧由狂人打招呼勿点发

## 验证

- 7 会话 `publish_request_status=none`（#14642 撤回后）
- 下次同类提审有「先问」出站记录
