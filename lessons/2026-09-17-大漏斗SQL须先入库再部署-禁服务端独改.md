# 大漏斗 SQL：服务端新于仓库时先拉回入库，禁止只改服务器

## 背景

bus#8782（知秋点名）：`dws_app_event_funnel_d_d_daily_stage_metrics.sql` 的 `video_play` 口径改动曾于 09-16 14:31 **只上服务端**，仓库仍停在旧版；与升维那次「仓库停 f1ab89ba 多日」是同一硬伤。

## 坑 / 错误做法

- 直接改 `/home/ec2-user/pipeline-runner/sql/...` 并当完成
- 用 `/tmp` 中转绕过仓库
- 只改 `ops_system/` 或只改 `pipeline-runner/` 一侧，两边长期分叉

## 正确做法（唯一合法顺序）

1. **服务器版比本地新** → 先把服务端文件拉回本地仓库作基线（`ops_system/.../spark/sql/` 与 `pipeline-runner/sql/` **两边都落**）
2. 在本地仓库改
3. 校验（行数 / `video_detail_uid` 等关键字 / md5）
4. `git commit` + `git push`
5. 再部署到服务端

判据：动作结束时 **本地仓库必须有新内容**；只在服务器上存在 = 违规。

- 服务端与本地 `pipeline-runner` / `ops_system` 三份 md5 均为 `440730fe69656a07c9a3ed308ee227bd`（541 行，含 `video_detail_uid`）
- 入库提交：`f34d51c8`（已在 `origin/dev`）
