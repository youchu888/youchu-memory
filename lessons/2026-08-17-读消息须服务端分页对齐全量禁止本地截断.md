# 读消息须服务端分页对齐全量，禁止本地截断漏读

## 背景

主人私聊#327：「读消息要从服务端对全部消息，不能少读或者漏读」。

此前 prompt 注入 `context_bridge` 只取本地 jsonl **最近 12 条**，`task_provenance` 只取 **最近 10 条**，且未在构建 prompt 前分页拉 agent-bus 服务端 inbox，导致跨多条私聊/派单时上下文缺失（与 bus#6586 快车道误结案同类根因：没看到完整指令）。

## 正确做法

1. **构建 prompt 前**：`sync_server_inbox_to_bridge()` → `fetch_inbox_paginated(after_id)` 分页拉全（1h 保鲜窗内），补写本地 bridge
2. **注入上下文**：`recent_context_block(full_sync=True)` 读**当日全部** bridge 记录（上限 500 防爆），回复展示放宽到 4000 字
3. **任务溯源**：`format_recent_block(full_sync=True)` 读当日全部 provenance
4. **又初行为**：处理私聊/派单前，以 prompt 内「当日全量」为准；若怀疑漏读，主动 `GET /inbox?after_id=N` 分页或读 `task_provenance.jsonl` 当日段，禁止只看尾部几条

## 验证

- `python3 -c "import context_bridge as cb; cb.recent_context_block(full_sync=True)"` 应含当日所有私聊#N
- 改完后须 **重启 tgbot**（`bash omdb/tgbot/restart.sh`）方生效
