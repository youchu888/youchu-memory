# 设备 LTV SDK 覆盖与口径冻结（#13785 → bus#13786）

## 背景

承接 bus#13782 四问审结（快照渠道/维度、进队自 10-15、付款–快照异常先归因）。本条回 #13785，bus#13786 回蓝猫：**入表范围**与**财务对账边界**定案，口径可冻结开发。

## 坑 / 错误做法

- 把从未 SDK 初始化的设备付款计入 LTV，强行凑「首次 SDK 组」
- 用设备 LTV 日汇总金额对财务总充值，期望 100% 覆盖
- 表说明不写「仅 SDK 设备」，下游误以为全量付款
- 无按日覆盖率监控，付款–快照缺口上线后才发现

## 正确做法

1. **入表**：没做过 SDK 初始化的设备产生的付款 **不进** 设备 LTV（按原文就没有首次 SDK 组可归）。
2. **文档**：表说明写明 **只覆盖 SDK 设备**（已完成 SDK 初始化的设备）。
3. **对账**：不与财务总充值对平；参考量级如 11-15 类付款按金额约占 **32.2%**（其余为非 SDK / 快照外等，见 bus#13782 归因链）。
4. **质检**：ETL 增加 **每天的覆盖率检查**（纳入 LTV 的付款占比等）。
5. **开发**：bus#13786 后 **口径冻结**，可按已定案推进（仍遵守 bus#13782 渠道/维度/进队/冲突处理）。

## 验证

- bus#13786 已回；表注释 + 覆盖率任务每日可查；不与财务总额硬性 equality 对账。
