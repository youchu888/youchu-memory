# 日报是汇报：禁内部黑话，要展开说，字数可略长

## 背景

主人 2026-07-28 纠正：日报不要写「只有我们知道的词」，要展开说；字数可以稍微多点——**这是要汇报的，不是总结**。此前 07-15 已定「通俗但正式」，但执行仍偏压缩黑话（如「姿态F六表与wrapper」「merge_pool下线」），部门读者读不懂。

## 坑 / 错误做法

- 写内部代号：姿态F、wrapper、merge_pool、半迁移、PI、col_list、hosts 等
- 为凑 20~30 字砍掉业务主语，变成「删旧daily、整wf验通」
- 把日报当工作总结压缩条，而不是给主管看的进展汇报

## 正确做法

1. 每条用业务话写清：**做了什么 → 对谁/哪块业务有用 → 结果**
2. 内部词必须展开或换成业务说法（例：wrapper→串行调度脚本；姿态F→按用户标签同款表设计；merge_pool→旧海豚合并任务）
3. 字数以说清为准，可 **40~70 字**；通常仍 3 条；禁口语俚语
4. 仍禁 bus#、机器人名、表名堆砌、代码记号直出
