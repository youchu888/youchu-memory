# 新建 dwd_r 须评估量级与分桶，默认不保留第一条

## 背景

新建 `dwd_*_r` 时若跳过评估，容易把 bucket 估小、或误开 `merge-engine=first-row`。bucket 建表后不可改；first-row 会让同 key 后写无法覆盖。

## 坑 / 错误做法

- 未跟业务确认事件/主键/是否需要 `_r` 就开写 DDL
- 不估增量、不查产线量级，直接抄 bucket=1 或 test 行数
- 习惯性写 `merge-engine=first-row`（「去重」≠「只留第一条」）

## 正确做法

新建前清单：

1. 跟业务确认：事件、主键粒度、实时表必要性、下游
2. 自估增量 + **prod** 探数（默认 T-1），对照现网同量级 fanout 表
3. 据此定 bucket / sinkParallelism；DDL、manifest、design 一致
4. **是否保留第一条：默认否**；仅特殊业务（如订单全局去重）才 `first-row`，并写明理由
5. 评估通过后再发斯科特合入 fanout

## 验证

- design / DDL 注释含：探数日、行数、bucket 依据、merge-engine 选择理由
- 非特殊场景 DDL 中 **无** `'merge-engine'='first-row'`
