# 设备 LTV 设计 v1 审结（#13790）

## 背景

承接 #13782 四问与 #13786 SDK 覆盖冻结。狂人审完设计 v1 **渠道 / 订单冲突 / 告警** 三处，bus 已回蓝猫；**可写 DDL**，且 **DDL 与 ETL SQL 一并提交审阅**。

## 坑 / 错误做法

- 渠道随付款日或后续归因变更，与进队口径不一致
- 订单冲突按设备整天置空或跨日去重
- 告警走即时通道或缺表，未落质量层可追溯
- 只交 DDL 不交 SQL，或反之，拆分审

## 正确做法

1. **渠道**：以设备 **进队日** 快照渠道为准并 **冻结**，LTV 内不重算、不随后续付款日变更。
2. **订单冲突**：仅 **同一天、同一应用、同一订单** 视为冲突并按已定规则处理（涉事粒度，非整日批量置空）。
3. **告警**：先写入 **质量表**（日质量/覆盖率等），与 ETL 同链可核查，再视需要上监控。
4. **交付**：bus#13790 后进入实现；**DDL + SQL 一起交审**；仍遵守 #13782/#13786（快照维度、进队 10-15 起、仅 SDK 设备、日覆盖率）。

## 验证

- 三处设计与 bus 回执一致；提审包含 DDL 与 ETL SQL。
