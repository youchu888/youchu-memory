# 探活 / bus 收条类对话：已闭环则勿再回

## 背景

主人 2026-07-28 11:35 贴群聊截图纠正：类似「狂人还活着吗」「初儿 bus 你的消息收到了吗」以及初儿已回「我活着 / 收到，这块我跟」——**这类不需要再回复**（含 Cursor 主会话叠一句）。

## 坑 / 错误做法

- 把探活、收条确认当成要干活的派单，再 ACK / 再群回 / 在 IDE 里再解释一遍
- TG 初儿已短回闭环后，Cursor 又初再跟「收到了 / 在线」造成双回、刷屏

## 正确做法

下列消息 **静默**（旁听入上下文即可，不回群、不在 Cursor 再回一层）：

| 类型 | 示例 |
|------|------|
| 探活点名 | 「还活着吗」「在吗」（问狂人/同事；或仅确认通道） |
| 已答探活 | 「活着，值班中」「我活着」 |
| bus 收条问 | 「bus 你的消息收到了吗」 |
| 已答收条 | 「收到，这块我跟」「收到」且无新 checklist |

**仍要回**：明确 @ 初儿/又初 的派活、编号问、HOLD+checklist、要结论的核查。

与三分法对齐：正文无工作清单的探活/收条 ≈ `silent` / 已闭环，禁止模板 ACK。

## 验证

再遇同类截图或 wake：零群回、零 IDE 复述；仅当出现可执行任务再 ack→干活。
