## 4. 说明与解读

### 4.1 day7 / day30 为 0

以核查日 **2026-05-21** 为准：

- **day7 = 0**：`dt >= 2026-05-15` 的 cohort 尚未满 7 天（例：05-15 + 7 日 = 05-22）。
- **day30 = 0**：`dt >= 2026-04-22` 的 cohort 尚未满 30 天；**04-20、04-21** 已有 day30 属正常（满龄日分别为 05-20、05-21）。

报表查询 dayN 时应限制：`dt <= CURRENT_DATE() - N`。

### 4.2 次日留存波动

- 多数 cohort **d1_pct 约 5.6% ~ 12%**。
- **2026-05-10**：注册量冲高（new ≈ 691 万），**d1_pct 仅 4.82%**，建议按 `app_code` 下钻是否个别项目拉新质量差（非表逻辑错误）。

### 4.3 日批与 hourly

- 近 10 日 `update_time` 统一为 **2026-05-21 11:30:06**，日批兜底在运行。
- 当日 cohort 的 day1 在白天可能随 **hourly INSERT INTO** 继续增大；**T+1 daily OVERWRITE** 为权威闭窗结果。

---

## 5. 建议跟进（非阻断）

1. 对 **2026-05-10** 按 `app_code` 做注册量与次日留存下钻。
2. 对外报表增加「cohort 是否满 N 日」标识，避免误读 0 为真实零留存。
3. 定期复用本报告 SQL 模板做月度巡检（守恒 + user_d_h 对账 + 满龄判断）。

## 6. 复现 SQL（生产只读）

```sql
-- 按日规模
SELECT dt,
  COUNT(*) AS dim_rows,
  BITMAP_UNION_COUNT(new_users) AS new_cnt,
  BITMAP_UNION_COUNT(day1_ret_cnt) AS d1_cnt,
  BITMAP_UNION_COUNT(day7_ret_cnt) AS d7_cnt,
  BITMAP_UNION_COUNT(day30_ret_cnt) AS d30_cnt
FROM dws.dws_app_retention_d_h
WHERE dt >= DATE_SUB(CURRENT_DATE(), INTERVAL 31 DAY)
  AND dt < CURRENT_DATE()
GROUP BY dt ORDER BY dt;

-- 守恒违规（应为 0 行）
SELECT dt FROM (
  SELECT dt,
    BITMAP_UNION_COUNT(new_users) AS n,
    BITMAP_UNION_COUNT(day1_ret_cnt) AS d1
  FROM dws.dws_app_retention_d_h
  WHERE dt >= DATE_SUB(CURRENT_DATE(), INTERVAL 31 DAY) AND dt < CURRENT_DATE()
  GROUP BY dt
) t WHERE d1 > n;

-- 与 user_d_h 对账（替换日期）
SELECT BITMAP_UNION_COUNT(new_users) FROM dws.dws_app_retention_d_h WHERE dt = '2026-05-18';
SELECT BITMAP_UNION_COUNT(new_users) FROM dws.dws_app_user_d_h WHERE dt = '2026-05-18';
```
