# SWZX-002 · 2026-11-03 使用时长为空排查

## 结论（一句话）
客户端几乎每个页面浏览都换新会话 ID（sid），会话墙钟时长恒为 0，无「有效会话」，汇总层自然无使用时长；不是调度漏跑。

## 证据链

| 层 | 11-03 结果 |
|----|-----------|
| 页面浏览明细 `dwd_app_page_view_d` | 135 行 / 有 uid 118 行；**118 个 sid 全部只有 1 次浏览** |
| 页面停留 `dwd_app_page_stay_d` | 118 行，`stay_sec` 全为 NULL（同 sid 无下一页，末页不计时） |
| 会话宽表 `dwm_app_session_sid_d` | 118 会话；**全部 bounce、时长 0、is_valid=0** |
| 使用时长汇总 `dws_session_duration_user_d` | **0 行**（日均只收有效会话；对照 SWZX-003 同日有数） |

样例用户 `426672`：约 26 分钟内 50 次浏览、**50 个不同 sid**（home→video_play→home… 每次换 sid）。

对照：同日 `SWZX-003` 有大量多 PV 有效会话，使用时长汇总有数。

## 根因归类
1. **主因（埋点/SDK）**：sid 未跨页面保持，会话被拆成单页 bounce。
2. **口径放大**：使用时长主指标用会话起止墙钟差；单 PV → 0 秒 → 不进有效档。
3. **停留旁路也失效**：page_stay 靠同 sid 相邻 PV 算差；一页一 sid → stay_sec 全空。
4. **非原因**：不是 11-03 分区没跑；DWM 有数；也不是产品在 dim 里被过滤（同线 SWZX-003 正常）。

## 建议
- 让客户端/SDK 排查 SWZX-002（尤其 iOS）会话 ID 生命周期：同一次冷启动/前台会话应复用 sid。
- 修复后从有稳定 sid 的业务日起再看使用时长；历史日无法靠补数「算出」真实时长。
