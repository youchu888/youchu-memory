1. 基点

本项目 = device_tag 迁移到 Spark + paimon 全链路。
框架 = Scala 元数据驱动 SQL 生成 (读元数据规则 → 动态生成 SQL → 执行) · daily 全量 INSERT OVERWRITE 快照姿态 · 完全对齐 user_tag 姿态 F。
规则 (lifecycle 分档 / pay 阈值 / video 7d / ad 7d) 配在元数据里，改元数据不改代码。
  • 粒度：(app_id, device_id) · 无 dt 分区 · daily INSERT OVERWRITE 全表覆写 (快照口径, 与 dim_user_all_d_d 姿态一致)
  • 兜底逻辑：daily 覆写做修正 — 每日一版快照，历史 device 属性有更新一次覆写掉
  • 调度：hadoop-1 独立 wrapper.sh 6 步 · cron 北京 11:00 = UTC 03:00
  • 下游：paimon → SR shadow (mysql cli INSERT OVERWRITE) 三档发布 (draft / test_om / prod_om)

3. dwd 上游数据源 (与 user_tag 同源)

上游 dwd喂给device_id 覆盖度
paimon.dwd.dwd_ad_event_r (or 等价)dwm_device_ad_d_d有 device_id
paimon.dwd.dwd_video_play_rdwm_device_video_d_d有 device_id
paimon.dwd.dwd_page_view_rdwm_device_active_d_d · dim_device_all_d_d有 device_id (主 pv 源)
paimon.dwd.dwd_login_v2_rdim_device_all_d_d有 device_id
paimon.dwd.dwd_order_paid_rdws_device_finance_d_d · dim_device_all_d_d大概率有 device_id (下单机型), 需 GO 前验证覆盖率
paimon.dwd.dwd_register_v2_rdim_device_all_d_d (register_time)大概率有 device_id (注册机), 需 GO 前验证覆盖率
GO 前验数点 A：dwd_order_paid_r / dwd_register_v2_r 里 device_id 空率若 >10%, dim_device_all_d_d 的 register_time / first_pay 列要用 uid 反向 lookup 该 uid 最近 pv/login 事件的 device_id 兜底 — 阶段 3 开发前先跑 SQL 出这两个源的 device_id null_rate。

4. dim_device_all_d_d · COALESCE 姿态 (承 user_tag 姿态 F)

每个属性列都套注册优先 + pv>login>paid 优先级兜底 pattern:

COALESCE(
  MIN_BY(CASE WHEN src='register' THEN <col> END, event_time),
  MIN_BY(CASE WHEN src IN ('pv','login','paid') THEN <col> END,
         named_struct('p', priority, 't', event_time))
) AS <col>
-- priority: pv=1, login=2, paid=3

register_time 特例: 无 register 兜底常量 2025-12-20 00:00:00 (与 user_tag 同)

6. wrapper 6 步流程

#!/bin/bash
# device_tag_wrapper.sh <dt> <profile: S|M|L>
# hadoop-1 · UTC 03:00 = 北京 11:00

dt=$1; profile=${2:-L}
log_dir=/home/ec2-user/spark/device_tag/logs
ts=$(date +%Y%m%d-%H%M%S)

set -e
spark-sql -f /home/ec2-user/spark/device_tag/sql/dwm_device_ad_d_d.sql       --hivevar dt=$dt   # step1
spark-sql -f /home/ec2-user/spark/device_tag/sql/dws_device_finance_d_d.sql  --hivevar dt=$dt   # step2
spark-sql -f /home/ec2-user/spark/device_tag/sql/dwm_device_video_d_d.sql    --hivevar dt=$dt   # step3
spark-sql -f /home/ec2-user/spark/device_tag/sql/dwm_device_active_d_d.sql   --hivevar dt=$dt   # step4
spark-sql -f /home/ec2-user/spark/device_tag/sql/dim_device_all_d_d.sql      --hivevar dt=$dt   # step5
spark-sql -f /home/ec2-user/spark/device_tag/sql/dws_device_tag_d_d.sql      --hivevar dt=$dt   # step6

# step7 · T2 SR shadow sync
mysql -h <SR_FE> -P 9030 -u admin -p"$SR_ADMIN_PWD" \
  -e "INSERT OVERWRITE dws.dws_device_tag_d_d_shadow SELECT * FROM paimon.dws.dws_device_tag_d_d;"

echo "=== wrapper ALL DONE dt=$dt ==="
资源模板锁 (对齐 user_tag)：--driver-memory 8g --executor-memory 12g --num-executors 30 --executor-cores 4 --conf spark.sql.shuffle.partitions=1600 --conf spark.sql.adaptive.*=true --conf spark.sql.defaultCatalog=paimon

8. cron 时点

0 3 * * * bash /home/ec2-user/spark/device_tag/wrapper.sh \
  $(TZ=Asia/Shanghai date -d yesterday '+\%Y-\%m-\%d') L \
  >> /home/ec2-user/spark/device_tag/logs/cron_$(date +\%Y\%m\%d).log 2>&1
cron 时点与 user_tag 冲突：user_tag 已占 UTC 03:00 (北京 11:00), yarn 资源同时段可能挤。
选项: (A) 串联 — user_tag wrapper 尾巴 append device_tag 6 步, 一个 cron 拖着跑 (~ 60-80 min) · (B) 错开 — device_tag 挪 UTC 05:00 (北京 13:00)。等钦定。

9. 验数 5 步 (对齐 user_tag)

  1. 行数总量: SELECT COUNT(*) FROM paimon.dws.dws_device_tag_d_d · 与 SR shadow 一致
  2. dt 范围: dim_device_all_d_d 无 dt 列, 用 MAX(last_login), MIN(register_time) 检查合理边界
  3. 采样 20 device 对比字段一致 (device_model / geo / channel / register_time / lifecycle_flag)
  4. SELECT lifecycle_flag, COUNT(*) FROM dws_device_tag_d_d GROUP BY 1 9 档分布合理 (不能全在一档)
  5. 前 10 大 app 行数 · 与 dim_user_all_d_d 各 app device/user 比 ~1.2-2.0 (每人 1-2 device 合理)
