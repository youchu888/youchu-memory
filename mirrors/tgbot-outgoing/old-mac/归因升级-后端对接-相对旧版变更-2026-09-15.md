# 归因升级 · 后端对接说明（相对旧版变更）

> **版本**：2026-09-15 · 又初  
> **用途**：说明升级后相对旧版**改了什么、怎么查、接口要不要动**  
> **环境**：test 能力已齐；prod 需先完成结果表加列 + 无候选表建表，再随日批发版  
> **旧字段字典**：`归因对接说明.md`（入围 / `is_run` / 新列以**本文**为准）

## 0. 三句话

1. **主读表不变**：列表 / 样本明细仍读 `dws.dws_register_attribution_result_d`（必带 `dt`）。
2. **升级主要改三块**：入围更严（双 flag）· 结果表多 6 个得分分项列 · 新增「无候选原因」ADS；汇总看板继续用 board。
3. **主列表过滤不用改**：仍 `IFNULL(is_run,0)=1`；`is_run` 只控**展示**，不再当开算白名单。

## 3. 入围口径（核心行为变化）

### 3.1 旧版

同时满足才算进结果表：

- 注册 `attribution_flag = 1`
- iOS + 自然/空渠道 + uid 非空
- **`dim_app_attribution_config.is_run = 1`（白名单开算）**

### 3.2 升级后

| 条件 | 说明 |
|------|------|
| 注册 `attribution_flag = 1` | `dwd.dwd_user_register_d_v2` |
| 安装 `attribution_flag = 1` | 同 `app_id` + `device_id` 的 `dwd.dwd_app_install_d` |
| 安装时间窗 | 安装 `event_time` ∈ **[注册 − 7 天, 注册 + 1 小时]**；取最近一条 |
| 设备 / 渠道 | iOS + 自然/空渠道 + uid 非空 |
| ~~`is_run = 1`~~ | **不再作为计算门槛** |

**产品 / 后端需知情**：缺安装 flag、或装机不在窗内 → **结果表无行**（不是失败行）。排查文案可提示查安装侧 `attribution_flag` 与时间窗。

### 3.3 打分 / 回写（不变）

- `is_active=1` 用专属分，否则回落 `app_id='default'`
- 回写仍靠 `is_rewrite_channel=1`；不改 `register_channel`

## 4. 结果表新列：实际得分评估

### 4.1 字段

| 列 | 类型 | 含义 |
|----|------|------|
| `score_brand` | INT | 品牌项**当时**实际加分 |
| `score_model` | INT | 型号项实际加分 |
| `score_system` | INT | 系统名项实际加分 |
| `score_system_version` | INT | 系统版本项实际加分 |
| `score_time` | INT | 时间衰减项实际加分 |
| `time_bucket_max_seconds` | INT | 命中时间档（如 600 / 3600 / 21600 / 86400） |

成功行校验：`score =` 五分项之和。

### 4.2 产品详情查询示例

```sql
SELECT
    AVG(score_brand) AS avg_score_brand,
    AVG(score_model) AS avg_score_model,
    AVG(score_system) AS avg_score_system,
    AVG(score_system_version) AS avg_score_system_version,
    AVG(score) AS avg_score_total,
    SUM(CASE WHEN time_bucket_max_seconds = 600   THEN 1 ELSE 0 END) AS cnt_10m,
    SUM(CASE WHEN time_bucket_max_seconds = 3600  THEN 1 ELSE 0 END) AS cnt_1h,
    SUM(CASE WHEN time_bucket_max_seconds = 21600 THEN 1 ELSE 0 END) AS cnt_6h,
    SUM(CASE WHEN time_bucket_max_seconds = 86400 THEN 1 ELSE 0 END) AS cnt_24h,
    AVG(CASE WHEN time_bucket_max_seconds = 600   THEN score_time END) AS avg_time_10m,
    AVG(CASE WHEN time_bucket_max_seconds = 3600  THEN score_time END) AS avg_time_1h,
    AVG(CASE WHEN time_bucket_max_seconds = 21600 THEN score_time END) AS avg_time_6h,
    AVG(CASE WHEN time_bucket_max_seconds = 86400 THEN score_time END) AS avg_time_24h
FROM dws.dws_register_attribution_result_d
WHERE dt BETWEEN '${start_dt}' AND '${end_dt}'
  AND app_id = '${app_id}'
  AND attribution_status = 'success';
```

- 成功数 = 0：均值展示 `-`，档位次数 0  
- 渠道详情：加 `AND attributed_channel = ?`  
- 档位秒数若产品自定义：建议 `GROUP BY time_bucket_max_seconds` 再映射文案，勿写死四档

### 4.3 样本明细

必带 `dt`。常用列：

`uid`, `register_event_id`, `source_event_id`, `source_event_type`, `source_event_time`,  
`score`, `score_threshold`, `confidence_level`, `attribution_status`, `unattributed_reason`,  
`time_diff_seconds`, `rewrite_status`, `rewrite_reason`, `rule_version`, `created_at`  
+ 本节 6 个新列（诊断用）

## 5. `is_run` / 配置表怎么用

| 项 | 约定 |
|----|------|
| 主列表 / 未传 `appId` | 只查 `IFNULL(is_run,0)=1` |
| `is_run=0` | 拉黑，不进主列表（传了具体 `appId` 仍可点开排查） |
| 日批 sync | 当日双 flag 入围且配置表**无行** → **INSERT** |
| 自动写入 | `is_run=1`，`is_active=0`（走 **default**），`is_rewrite_channel=0`，打分列抄 default 占位 |
| 改默认规则 | 后台改 `app_id='default'` |
| 特殊规则 | 对该 app 设 `is_active=1` 并改分 |
| 拉黑后 | sync **不 UPDATE** 已有行 → 不会被刷回 |
| 结果表 ETL | **不读** `is_run` |

**后端**：Mapper 过滤**保持**现网即可；配置页勿再写「`is_run` = 唯一开算」。自动开的产品 `is_active=0` 表示走 default。

## 6. 新表：无候选原因

### 6.1 读法

表：`ads.ads_register_attribution_no_candidate_reason_d_d`  
粒度：`dt × app_id × reason_code`  
**不要**用结果表 `unattributed_reason` 拼无候选（无候选多数不落结果表）。

```sql
SELECT
    reason_code,
    reason_name,
    SUM(register_cnt) AS register_cnt
FROM ads.ads_register_attribution_no_candidate_reason_d_d
WHERE dt BETWEEN '${start_dt}' AND '${end_dt}'
  AND app_id = '${app_id}'
GROUP BY reason_code, reason_name
ORDER BY register_cnt DESC;
```

多日：按 reason `SUM`，不要对每日行数取平均。某原因为 0 时表可无行。

### 6.2 原因码（固定，互斥，按序归类）

| reason_code | reason_name |
|-------------|-------------|
| `reg_ip_empty` | 注册IP为空 |
| `no_landing_same_ip` | 无同app同IP落地页 |
| `landing_channel_organic_or_empty` | 同IP落地页渠道均为空或organic |
| `time_not_met` | 非自然落地页不满足注册前24小时窗 |
| `uncategorized` | 未归类 |

前端直接展示接口返回的 code / name，不要自行推断文案。

### 6.3 与看板对账

同日同 `app_id`（board 跨渠道含 NULL 桶汇总）：

```text
SUM(no_candidate.register_cnt)
  ≈ SUM(board.eligible_register_cnt) - SUM(board.has_candidate_cnt)
```

## 7. 汇总看板（board）怎么用

表：`ads.ads_register_attribution_board_d_d`  
粒度：`dt × app_id × attributed_channel`（渠道可为 NULL）

- 只存**可加计数**；覆盖率 / 成功率 / 平均分 = 查询侧 `SUM` 后相除  
- 填了 uid / 分数区间 / 归因状态 / 置信度 / 来源类型 / 未归因原因 → **必须走结果表**，不能只查 board  
- 产品状态、写回状态汇总规则见专题：`../05.ads/ads_register_attribution_board_d_d/归因看板-后端对接-2026-09-10.md`

常用计数列：`eligible_register_cnt`、`has_candidate_cnt`、`attribution_success_cnt`、`high_confidence_cnt`、写回五类 `rewrite_*_cnt`、分数档 `score_*_cnt`、`score_sum`、`time_diff_seconds_sum`、`click_success_cnt` / `view_success_cnt`。

### 9.1 prod 发版前 DDL（运维执行）

**改表**：

```sql
ALTER TABLE dws.dws_register_attribution_result_d
  ADD COLUMN score_brand INT NULL COMMENT '品牌项实际加分(计算当时)' AFTER score;

ALTER TABLE dws.dws_register_attribution_result_d
  ADD COLUMN score_model INT NULL COMMENT '型号项实际加分(计算当时)' AFTER score_brand,
  ADD COLUMN score_system INT NULL COMMENT '系统名项实际加分(计算当时)' AFTER score_model,
  ADD COLUMN score_system_version INT NULL COMMENT '系统版本项实际加分(计算当时)' AFTER score_system,
  ADD COLUMN score_time INT NULL COMMENT '时间衰减项实际加分(计算当时)' AFTER score_system_version,
  ADD COLUMN time_bucket_max_seconds INT NULL COMMENT '命中时间档max_seconds' AFTER time_diff_seconds;
```

**建表**：

```sql
CREATE TABLE IF NOT EXISTS ads.ads_register_attribution_no_candidate_reason_d_d (
    dt              DATE                 NOT NULL COMMENT '注册业务自然日(分区键)',
    app_id          VARCHAR(64)          NOT NULL COMMENT '产品ID',
    reason_code     VARCHAR(64)          NOT NULL COMMENT '无候选原因码',
    reason_name     VARCHAR(128) REPLACE NULL     COMMENT '原因名称(与 reason_code 固定映射)',
    register_cnt    BIGINT REPLACE       NOT NULL DEFAULT '0' COMMENT '该原因下无候选入围注册数',
    etl_batch_id    VARCHAR(128) REPLACE NULL COMMENT '发布批次(预留)',
    updated_at      DATETIME REPLACE     NULL COMMENT '本次写入时间'
)
ENGINE = OLAP
AGGREGATE KEY (dt, app_id, reason_code)
COMMENT '注册归因无候选原因日汇总(入围无候选五类互斥拆解)'
PARTITION BY RANGE (dt) ()
DISTRIBUTED BY HASH (app_id) BUCKETS 8
PROPERTIES (
    "replication_num" = "3",
    "compression" = "LZ4",
    "dynamic_partition.enable" = "true",
    "dynamic_partition.time_unit" = "DAY",
    "dynamic_partition.start" = "-10000",
    "dynamic_partition.end" = "3",
    "dynamic_partition.history_partition_num" = "30",
    "dynamic_partition.prefix" = "p",
    "dynamic_partition.time_zone" = "Asia/Shanghai",
    "dynamic_partition.buckets" = "8"
);
```

列已存在 / 表已存在则跳过对应语句。
