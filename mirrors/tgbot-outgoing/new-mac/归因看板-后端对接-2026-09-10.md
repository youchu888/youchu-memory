# 归因看板 / 归因结果 · 后端对接说明

> **版本**：2026-09-10b · 又初  
> **用途**：对齐「归因结果」页查询条件 + 汇总指标怎么算、查哪张表  
> **截图依据**：查询条件面板（日期 / APP / 渠道 / 写回 / 归因状态 / 置信度 / 产品状态 / 来源类型 / 未归因原因 / 分数区间 / uid / register_event_id）

## 0. 先分清两张表

截图里的条件**混了汇总筛选和明细筛选**，不能全打在一张 ADS 上。

| 能力 | 表 | 粒度 | 典型用途 |
|------|----|------|----------|
| **汇总看板**（测试验证产品行 / 正式运营渠道行） | `ads.ads_register_attribution_board_d_d` | `dt × app_id × attributed_channel` | 入围/覆盖率/成功率、渠道平均分等 |
| **归因结果表明细**（列表 / 导出 / uid 精确查） | `dws.dws_register_attribution_result_d` | 注册事件一行 | 状态、分数、来源类型、未归因原因、uid |

```text
日批：注册+安装入围 → 结果表打分落行 → 渠道回写 apply → ADS 看板按渠道汇总
查询：汇总读 ADS；明细读结果表（必须带 dt 区间）
```

## 1. 查询条件一览（对接截图）

| # | UI 条件 | 参数建议 | 作用表 | 字段 / 规则 |
|---|---------|----------|--------|-------------|
| 1 | 日期范围 | `start_dt`, `end_dt` | **两表都必带** | `dt BETWEEN start AND end`（注册业务日，含首尾） |
| 2 | APP_ID | `app_id` / 全部 | 两表 | `app_id = ?`；「全部」= 展示范围内全部 `is_run=1` 产品，**不改入围口径** |
| 3 | 归因渠道 | `attributed_channel` 模糊/精确 | 两表 | 结果：`attributed_channel LIKE/ =`；看板：同字段（可为 NULL） |
| 4 | 写回状态 | `rewrite_status` 枚举 | **明细=结果表**；汇总=看板现算 | 见 §2.1 |
| 5 | 归因状态 | `attribution_status` | **仅结果表** | `success` / `unattributed` |
| 6 | 置信度等级 | `confidence_level` | **仅结果表**（汇总高置信用计数现算） | `high` / `medium` / `unattributed` |
| 7 | 产品状态 | `product_status` | **仅看板现算** | 见 §2.2（不落表） |
| 8 | 来源事件类型 | `source_event_type` | **仅结果表** | `landing_page_click` / `landing_page_view` |
| 9 | 未归因原因 | `unattributed_reason` | **仅结果表** | 如 `score_below_threshold`；无候选一般不落行 |
| 10 | 分数区间 | `score_min`, `score_max` | **仅结果表** | `score BETWEEN min AND max`（可只填一侧） |
| 11 | 用户 ID | `uid` | **仅结果表** | **精确** `uid = ?` |
| 12 | 注册事件 ID | `register_event_id` | **仅结果表** | **精确** `register_event_id = ?` |

### 1.1 接口怎么拆（建议）

| 接口 | 读表 | 接受的条件 |
|------|------|------------|
| 汇总列表（测试验证 / 正式运营） | ADS | 日期、APP、渠道、**产品状态**、**写回状态（产品/渠道级现算）** |
| 明细列表 / 导出 | 结果表 | 日期、APP、渠道、写回、归因状态、置信度、来源类型、未归因原因、分数区间、uid、register_event_id |
| 明细里「产品状态」 | — | **不要**当结果表列；若 UI 同屏展示，用 ADS 先算出产品集合再 `app_id IN (...)` 过滤明细 |

填了 uid / register_event_id / 分数 / 归因状态 / 置信度 / 来源类型 / 未归因原因 → **必须走结果表**，不能只查 ADS。

## 2. 条件取值与判定

### 2.1 写回状态（UI「写回状态」）

结果表原始字段：`rewrite_status`（`1`/`0`/`NULL`）+ `rewrite_reason`。

| UI / API 建议值 | 明细判定（结果表） | 汇总判定（ADS，先 SUM 再判） |
|-----------------|--------------------|------------------------------|
| `success` | `rewrite_status = 1` | `rewrite_success_cnt > 0`（产品级优先级见下） |
| `failed` | `rewrite_status = 0` | `rewrite_fail_cnt > 0` 优先 |
| `skipped` | 状态空且 reason ∈ `未回写-app未灰度`、`已有真实渠道-免归因` | `rewrite_skipped_cnt` |
| `not_writeback` | 状态空且 reason = `未回写-归因仍organic` | `rewrite_not_writeback_cnt` |
| `unknown` | 成功内其余 | `rewrite_unknown_cnt` |
| `none` / 全部里的「无成功可写回」 | 无成功行 | 产品 `attribution_success_cnt=0` |

**产品级写回状态优先级（汇总）**：`none`（成功=0）→ `failed` → `success` → `skipped` → `not_writeback`（未知可单独或并入 unknown）。

### 2.2 产品状态（UI「产品状态」）— 只现算，不落表

对每个 `app_id`，日期区间内跨渠道汇总：

```text
E = SUM(eligible_register_cnt)
C = SUM(has_candidate_cnt)
S = SUM(attribution_success_cnt)
```

| UI 文案 | 判定 |
|---------|------|
| 有归因成功 | `S > 0` |
| 有候选无成功 | `S = 0 AND C > 0` |
| 有入围无候选 | `E > 0 AND C = 0` |

「全部」= 不按状态滤；先定产品集合再算其它模块。

### 2.3 归因状态 / 置信度 / 来源类型 / 未归因原因（结果表）

| 字段 | 取值 | 说明 |
|------|------|------|
| `attribution_status` | `success` / `unattributed` | 成功 = 过线；未归因 = 有候选未过线 |
| `confidence_level` | `high` / `medium` / `unattributed` | 高置信复用结果表字段 |
| `source_event_type` | `landing_page_click` / `landing_page_view` | 点击 / 展示 |
| `unattributed_reason` | 如 `score_below_threshold` | **无候选注册不进结果表**，筛 `no_candidate` 通常 0 行 |

### 2.4 APP「全部产品」

读 `dim.dim_app_attribution_config` 当前 `is_run = 1` 的真实 `app_id`。  
`is_run` **只控展示范围**，不参与入围计算（V1.0.11）。

## 3. 明细查询示例（结果表）

```sql
SELECT
    dt, app_id, uid, register_event_id, register_event_time,
    attributed_channel, attribution_status, confidence_level,
    score, score_threshold, time_diff_seconds,
    source_event_type, source_event_id, source_event_time,
    unattributed_reason,
    rewrite_status, rewrite_reason
FROM dws.dws_register_attribution_result_d
WHERE dt BETWEEN '${start_dt}' AND '${end_dt}'          -- 必填
  AND ('${app_id}' = '' OR app_id = '${app_id}')
  AND ('${channel}' = '' OR attributed_channel LIKE CONCAT('%', '${channel}', '%'))
  AND ('${attr_status}' = '' OR attribution_status = '${attr_status}')
  AND ('${confidence}' = '' OR confidence_level = '${confidence}')
  AND ('${src_type}' = '' OR source_event_type = '${src_type}')
  AND ('${unattr_reason}' = '' OR unattributed_reason = '${unattr_reason}')
  AND (${score_min} IS NULL OR score >= ${score_min})
  AND (${score_max} IS NULL OR score <= ${score_max})
  AND ('${uid}' = '' OR uid = '${uid}')                 -- 精确
  AND ('${register_event_id}' = '' OR register_event_id = '${register_event_id}')
  -- 写回状态：按 §2.1 展开 CASE / OR，勿只写 rewrite_status=1
ORDER BY dt DESC, register_event_time DESC
LIMIT ${limit} OFFSET ${offset};
```

导出：同一 WHERE，去掉分页；注意大区间 + 全产品扫表成本。

## 4. 汇总看板（ADS）— 落表与现算

### 4.1 一句话

日表只存**可加计数**（22 列）。比率 / 均值 / 产品状态：**先 SUM 再算**，禁止对每日比率取平均。

### 4.2 漏斗

```text
入围 ⊃ 有候选 ⊃ 成功
入围 − 有候选 = 入围但无候选
```

| 字段 | 含义 |
|------|------|
| `eligible_register_cnt` | 入围（V1.0.11，含无候选） |
| `has_candidate_cnt` | 有有效 `source_event_id` |
| `attribution_success_cnt` | `attribution_status='success'` |
| `high_confidence_cnt` | 成功且 `confidence_level='high'` |

### 4.3 22 列摘要

- 维：`dt`, `app_id`, `attributed_channel`（可为 NULL）  
- 漏斗 4 + 写回五态 5 + 分数四档 4  
- 新增可加：`score_sum`, `time_diff_seconds_sum`, `click_success_cnt`, `view_success_cnt`  
- 审计：`etl_batch_id`, `updated_at`

| 现算 | 公式 |
|------|------|
| 候选覆盖率 | `SUM(has_candidate_cnt) / SUM(eligible_register_cnt)` |
| 归因成功率 | `SUM(attribution_success_cnt) / SUM(has_candidate_cnt)` |
| 高置信占比 | `SUM(high_confidence_cnt) / SUM(attribution_success_cnt)` |
| 平均分 | `SUM(score_sum) / SUM(attribution_success_cnt)` |
| 平均注册间隔(秒) | `SUM(time_diff_seconds_sum) / SUM(attribution_success_cnt)` |
| 点击/展示占比 | `click / (click+view)`，`view / (click+view)` |

覆盖率/成功率务必**跨渠道桶（含 NULL）**汇总后再除。

### 4.4 汇总在查询条件下的用法

| 条件 | 汇总侧处理 |
|------|------------|
| 日期、APP、渠道 | 直接 `WHERE` ADS |
| 产品状态 | HAVING / 外层按 §2.2 过滤 `app_id` |
| 写回状态 | 产品或渠道级按 §2.1 现算后再滤 |
| 归因状态、置信度、来源类型、未归因、分数、uid、register_event_id | **汇总接口忽略或拒绝**；改查明细 |

```sql
-- 测试验证：产品行
SELECT app_id,
       SUM(eligible_register_cnt) AS eligible,
       SUM(has_candidate_cnt) AS candidate,
       SUM(attribution_success_cnt) AS success,
       SUM(has_candidate_cnt) / NULLIF(SUM(eligible_register_cnt), 0) AS coverage_rate,
       SUM(attribution_success_cnt) / NULLIF(SUM(has_candidate_cnt), 0) AS success_rate
FROM ads.ads_register_attribution_board_d_d
WHERE dt BETWEEN '${start}' AND '${end}'
  AND app_id IN (/* is_run=1 且通过产品状态过滤 */)
GROUP BY app_id
HAVING SUM(eligible_register_cnt) > 0;
```
