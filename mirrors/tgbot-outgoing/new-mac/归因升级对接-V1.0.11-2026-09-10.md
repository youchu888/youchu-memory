## 0. 先答：有没有新增表 / 字段？

| 问题 | 答案 |
|------|------|
| **后端要不要接新表？** | **不用。** 结果仍查 `dws.dws_register_attribution_result_d`；配置仍是 `dim.dim_app_attribution_config` / `dim.dim_app_attribution_time_config` |
| **结果表有没有新列？** | **V1.0.11 本身不加列。** 列集合与升级前一致（含更早两阶段已有的 `rewrite_status` / `rewrite_reason`） |

| **那升级改了什么？** | **入围口径**（怎么进结果表）+ **`is_run` 语义**（不再卡计算，改由日批同步供展示）+ **旧看板任务停产** |

数仓侧新增的是 **ETL 任务** `dim_app_attribution_config_is_run_sync_d`（回写配置表 `is_run`），**不是**给后端新查的业务表。

## 1. 一句话

日批仍产出「注册归因结果行」；谁进表从「配置白名单 `is_run=1`」改为「**注册 + 安装双 `attribution_flag=1`**」；`is_run` 改成「当日有入围则同步为 1」的**展示/运营开关**，不再作为「能不能算」的硬门槛。

---

## 2. 链路（升级后）

```text
注册(flag=1) ∩ 安装(flag=1, 同 device, 时间窗)
        ↓
dws_register_attribution_result_d   ← 后端主读
        ↓
dim_user_attribution_channel_apply_d  （仅 is_rewrite_channel=1 时改 dim_user_all.channel）
        ↓
dim_app_attribution_config_is_run_sync_d  （对当日入围 app：INSERT 缺失 / UPDATE is_run=1）
        ↓
metrics / dashboard_ext               ← 已停产（占位空跑，勿再对接旧看板表）
```

工作流：仍在 `wf_dws_汇总_日`（日批 T-1）。

## 4. 入围口径（相对旧版的核心变化）

### 4.1 旧版（升级前）

同时满足才算：

- `user_register.attribution_flag = 1`
- iOS + 自然渠道（organic / 空）+ uid 非空
- **`dim_app_attribution_config.is_run = 1`（白名单开算）**

### 4.2 新版（V1.0.11）

同时满足才进结果表计算：

| 条件 | 说明 |
|------|------|
| 注册 `attribution_flag = 1` | `dwd.dwd_user_register_d_v2` |
| 安装 `attribution_flag = 1` | 同 `app_id` + `device_id` 的 `dwd.dwd_app_install_d` |
| 安装时间窗 | 安装 `event_time` ∈ **[注册 − 7 天, 注册 + 1 小时]**；取最近一条 |
| 设备 / 渠道 | iOS + 自然/空渠道 + uid 非空 |
| ~~`is_run = 1`~~ | **不再作为计算门槛** |

**影响（后端/产品需知情）**：缺安装侧 flag、或装机不在窗内 → **不出结果行**（与「无落地页候选不落行」同类：不是失败行，是根本没有记录）。入围量可能低于旧白名单期，属预期。

### 4.3 打分（不变）

- 产品有 `is_active=1` 专属配置 → 用专属；否则回落 `app_id='default'`
- 时间档同理回落 `default`
- 公式 / 阈值 / click 优先于 view：与旧版一致

### 4.4 渠道回写（不变）

- 仍由 `dim_user_attribution_channel_apply_d` 执行
- 仅当 `is_rewrite_channel = 1` 且归因 `success` 等条件满足时改 `dim_user_all.channel`（及当日快照）
- **不改** `register_channel`

## 5. `is_run` 新语义（配置表）

| 项 | 旧 | 新（V1.0.11） |
|----|----|----------------|
| 对 ETL | `is_run=1` 才参与归因计算 | **计算不读 `is_run`** |
| 对前端/运营 | 「是否开通归因」 | **展示向**：当日有入围后，sync 任务会把该 app **置为 `is_run=1`** |
| sync 行为 | — | INSERT：config 无行则从 `default` 拷打分，`is_run=1`，`is_rewrite_channel=0`；UPDATE：已有行且 `is_run≠1` → 只改 `is_run=1` |
| 不会做的事 | — | **不**自动把未入围 app 置 `0`；**不**改 `is_rewrite_channel` / 打分项 |

对接建议：

- 列表「是否参与归因计算」若仍绑 `is_run`：理解成 **运营展示开关 + 日批同步结果**，不是实时入围真相源。
- 入围真相源：看结果表是否有行，或上游双 flag；不要再用「`is_run=0` ⇒ 一定没算」解释空结果。

## 6. 结果表字段（提醒：无新增）

粒度、主键、分区与旧版相同：`(dt, app_id, uid, register_event_id)`，**查询必带 `dt`**。

常用列（完整字典见旧对接说明 §3.1）：

| 分组 | 字段 |
|------|------|
| 基础 | `dt`, `app_id`, `uid` |
| 结果 | `attributed_channel`, `attribution_status`, `confidence_level`, `score`, `score_threshold` |
| 来源 | `source_event_id`, `source_event_type`, `source_event_time` |
| 未过 | `unattributed_reason` |
| 回写展示（更早已有） | `rewrite_status`（1/0/NULL）, `rewrite_reason` |
| 元数据 | `rule_version`, `created_at` |

**仍成立的硬口径**：

1. 至少匹配到一个落地页候选（同 app + 同 IP 的 click/view）才会进表。  
2. 完全没有候选 → **不落行**（不是 `unattributed` 行）。  
3. 有候选但分数不够 → 有行，`attribution_status = 'unattributed'`。

## 7. 旧看板停产

| 原任务 / 表 | 状态 | 后端动作 |
|-------------|------|----------|
| `dws_register_attribution_metrics_d_d` | 占位空跑，不写业务数 | **停用依赖**；成功率请对结果表自行 `GROUP BY` |
| `dws_register_attribution_dashboard_ext_d` 等 | 同上 | **停用** |

结果表侧成功率示例：

```sql
SELECT dt, app_id,
       COUNT(*) AS total_rows,
       SUM(attribution_status = 'success') AS success_cnt,
       ROUND(SUM(attribution_status = 'success') / COUNT(*), 4) AS success_rate
FROM dws.dws_register_attribution_result_d
WHERE dt = '${biz_date}'
GROUP BY dt, app_id;
```

> 分母 = 「进了结果表的注册」（双 flag 入围且有落地页候选），**不是**全部 iOS organic 注册。
