# 大漏斗（事件漏斗）· 后端对接说明（升维版）

> **版本**：V2 · 2026-09-10 · 又初  
> **相对 V1 变更**：主键/粒度新增 `device_type`、`source_type`（注册设备 + 自然/渠道）  
> 表名：`dws.dws_app_event_funnel_d_d` · session：`dev-20260807-big-funnel-001`  
> 口径权威：`metric_big_funnel_event_dictionary`  
> 用途：与后端对齐 **查哪张表、新字段取值、怎么筛、怎么上卷、转化率怎么算**

---

## 0. 相对旧版改了什么（必读）

| 项 | 旧（V1） | 新（V2） |
|----|----------|----------|
| 粒度 / 主键 | `(dt, app_id, is_new)` | `(dt, app_id, is_new, device_type, source_type)` |
| 行数量级 | 约 3 行 / app / 天 | 约十几行 / app / 天（组合稀疏，不会满打满算） |
| 设备 | 无 | `device_type`：注册时设备 |
| 用户来源 | 无 | `source_type`：`organic` / `channel`（对接口 `sourceTypeList`） |
| 查询 | 按新老筛即可 | 可再按设备、自然/渠道筛；不筛时要对指标 **SUM 上卷** |

**兼容注意**：旧 SQL 若只 `WHERE is_new=1` 且假定一行，升维后会变成多行，必须 `SUM` 或显式筛 `device_type` / `source_type`。

---

## 1. 一句话

按 **天 × 产品 × 新老 × 注册设备 × 注册来源** 产出 **18 个业务事件** 的 **用户数 / 会话数 / 事件数**（宽表 54 指标列，空填 `0`）。  
各事件 **独立** `COUNT(DISTINCT uid)`，不是「上一事件人群里再筛」；**漏斗转化率不落库**，查询侧用 `*_user_cnt` 现算。

## 2. 主表

| 项 | 说明 |
|----|------|
| **表名** | `dws.dws_app_event_funnel_d_d` |
| **粒度 / 主键** | `(dt, app_id, is_new, device_type, source_type)` |
| **分区** | `dt`；**查询必须带 dt** |
| **用户数口径** | 只认账号 `uid`；**不用 `device_id` 计人** |
| **产出** | Spark → Paimon（主）；SR DDL 备同步，勿默认当海豚 SR 日批表 |
| **业务日** | T-1 |
| **上游** | 事件：`paimon.dwd.*_r`；设备/来源：**仅** `dwd.dwd_user_register_d_v2_r`（**不读 dim**） |

### 勿对接

- 中间长表 `dws.dws_app_event_funnel_metric_stg_d`
- 细渠道码进主键（只要自然/渠道两档）
- 事件发生时的设备（PV/播放一律挂**注册设备**）
- 落库转化率字段

## 3. 维度字段

| 字段 | 类型 | 取值 / 说明 |
|------|------|-------------|
| `dt` | DATE / STRING | 业务日（分区） |
| `app_id` | VARCHAR / STRING | 产品 ID |
| `is_new` | TINYINT / INT | `1` 新 · `0` 老 · `-1` 无 uid |
| `device_type` | VARCHAR / STRING | `IOS` / `ANDROID` / `PC` / `OTHER` |
| `source_type` | VARCHAR / STRING | `organic`（自然）/ `channel`（有真实渠道码） |
| `update_time` | DATETIME | ETL 写入时刻，一般不展示 |

### 3.1 `is_new`

| 值 | 含义 | 接口 |
|----|------|------|
| `1` | 当日有注册事件的 uid；当天行为都算新 | 「仅新」；**注册→xxx 转化只用这一档** |
| `0` | 有 uid、当日未注册 | 「仅老」；本档 `user_register_*` **恒为 0** |
| `-1` | 无 uid | 单独档，勿并进 `0` |

### 3.2 `device_type`（注册设备）

| 值 | 含义 |
|----|------|
| `IOS` / `ANDROID` / `PC` | 注册事件 `device` 归一 |
| `OTHER` | 注册设备无法归一，或无 uid；**不是**「用户选了其它设备」的业务枚举 |

规则：

- **只认注册时设备**；页面/视频等事件不看当条 `device`
- 挂维：`dwd_user_register_d_v2_r` —— 当日注册优先，否则该 uid 在 `dt≤业务日` 的历史首次注册
- 对不上注册记录时，实现侧会落到 `OTHER`（工程兜底，见 §6）

### 3.3 `source_type`（用户来源 = 自然 / 渠道）

对接口字段：`sourceTypeList`（`organic` / `channel`）。

| 值 | 判定（注册时 `channel`） |
|----|--------------------------|
| `organic` | `organic` / `self` / `natural` / 空 / null，以及其余非真实投放码 |
| `channel` | 有真实渠道码（非上列自然类） |

**不是**细渠道名；细渠道不下钻本表。

### 3.4 取值样例（test · YC-001 · 2026-09-04）

新用户注册拆开（合计 = 61,697）：

| device_type | source_type | 注册 UV |
|-------------|-------------|---------|
| ANDROID | channel | 30,217 |
| ANDROID | organic | 12,949 |
| IOS | organic | 10,015 |
| IOS | channel | 8,516 |

当日宽表实际出现组合：**12 行**（含老用户、无 uid 档）。

## 4. 指标字段（18 × 3 = 54）

命名：`<前缀>_user_cnt` / `_session_cnt` / `_event_cnt`，`bigint`，无数据填 **`0`**。

| 中文 | 前缀 |
|------|------|
| 安装 | `app_install` |
| 注册 | `user_register` |
| 登录 | `user_login` |
| 下单 | `order_created` |
| 支付 | `order_paid` |
| 金币消耗 | `coin_consume` |
| SDK 初始化 | `sdk_init` |
| 页面展示（多页） | `app_page_view` |
| 页面点击 | `page_click` |
| 视频展示 | `video_view` |
| 视频有效观看 | `video_play` |
| 视频购买 | `video_purchase` |
| 小说展示 / 阅读 / 购买 | `novel_view` / `novel_read` / `novel_purchase` |
| 漫画展示 / 阅读 / 购买 | `comic_view` / `comic_read` / `comic_purchase` |

| 后缀 | 含义 |
|------|------|
| `_user_cnt` | `COUNT(DISTINCT uid)`，无 uid 不计 |
| `_session_cnt` | `COUNT(DISTINCT sid)` |
| `_event_cnt` | 符合条件的事件行数 |

### 事件筛选摘要

| 前缀 | 筛选 |
|------|------|
| 安装/注册/登录/下单/支付/金币/SDK/点击/*_purchase | `event = '…'` |
| `app_page_view` | 当日 uid 下 `page_key` 去重 **>1** |
| `video_view` | `video_behavior_key = 'video_view'`（小写） |
| `video_play` | 有效观看四条件任一成立 |
| `novel_view` / `comic_view` | `*_behavior_key = 'VIEW'`（全大写） |
| `novel_read` / `comic_read` | 翻页/完成 + READ 变体 |

**视频有效观看（任一）**：`play_duration≥5` · `video_duration*play_progress≥5` · `video_complete` · `play_progress≥0.01`

## 5. 查询与上卷

### 5.1 转化率（接口现算，不落库）

| 示例 | 公式 | 注意 |
|------|------|------|
| 注册→登录 | `user_login_user_cnt / user_register_user_cnt` | 分母 0 → `null` |
| 展示→有效观看 | `video_play_user_cnt / video_view_user_cnt` | 分母 0 → `null` |
| 注册→有效观看 | 同上注册分母 | **仅 `is_new=1`** |

先对分子分母 **SUM 上卷，再除**；禁止对行级比率 `AVG`。

### 5.2 上卷

| 场景 | 做法 |
|------|------|
| 不限设备/来源/新老 | 对指标列 **`SUM`** |
| 只要新+老 | `WHERE is_new IN (0,1)` 再 `SUM` |
| 接口 `sourceTypeList` / 设备多选 | `source_type IN (...)` / `device_type IN (...)` 再 `SUM` |
| 多日 · 事件/会话 | 可 `SUM` |
| 多日 · **用户数** | **禁止**直接 `SUM(*_user_cnt)` |
| 跨 app | **禁止**把多 app 的 `user_cnt` 加成「全站 UV」 |

### 5.3 示例 SQL

**列表（带新维）**

```sql
SELECT
  dt, app_id, is_new, device_type, source_type,
  user_register_user_cnt,
  user_login_user_cnt,
  video_view_user_cnt,
  video_play_user_cnt
FROM dws.dws_app_event_funnel_d_d
WHERE dt = '${biz_date}'
  AND app_id = '${app_id}'
ORDER BY is_new, device_type, source_type;
```

**注册→有效观看（仅新用户；可再筛设备/来源）**

```sql
SELECT
  dt, app_id, device_type, source_type,
  user_register_user_cnt,
  video_play_user_cnt,
  CASE WHEN user_register_user_cnt > 0
       THEN video_play_user_cnt * 1.0 / user_register_user_cnt END AS register_to_play_rate
FROM dws.dws_app_event_funnel_d_d
WHERE dt = '${biz_date}'
  AND app_id = '${app_id}'
  AND is_new = 1;
```

**不限设备/来源时上卷（兼容旧「一天一行」用法）**

```sql
SELECT
  dt, app_id,
  SUM(user_register_user_cnt) AS user_register_user_cnt,
  SUM(user_login_user_cnt) AS user_login_user_cnt,
  SUM(video_view_user_cnt) AS video_view_user_cnt,
  SUM(video_play_user_cnt) AS video_play_user_cnt
FROM dws.dws_app_event_funnel_d_d
WHERE dt = '${biz_date}'
  AND app_id = '${app_id}'
  AND is_new IN (0, 1)
GROUP BY dt, app_id;
```

## 6. 易错点

1. **升维后多行**：旧代码假定 `(dt,app_id,is_new)` 唯一 → 必须改成带新维或 `SUM`。
2. **账号口径**：用户数只认 `uid`。
3. **大小写**：视频 `video_view` 小写；小说/漫画展示 `VIEW` 全大写。
4. **页面展示**：当日 uid 的 `page_key` 去重 >1，不是全部 page_view。
5. **独立计人**：未拆 `is_new` 时全站观看常大于当日注册，不是清洗坏了；「注册→观看」只用 `is_new=1`。
6. **`OTHER` 兜底**：老用户若在注册 `_r` 挂不上历史注册，设备/来源会落到 `OTHER`+`organic`（工程默认，非产品枚举「其它」）。筛设备时注意这块会偏大。
7. **注册业务日**：当前按分区 `dt`；与活跃「新增」按 `event_time` 可能不一致（另文确认中）。

## 7. 接口字段建议

| JSON（示例） | 表字段 |
|--------------|--------|
| `dt` / `appId` / `isNew` / `deviceType` / `sourceType` | 对应维度 |
| `userRegisterUserCnt` 等 | `*_user_cnt` |
| `sourceTypeList` 入参 | 空=不限；有值则 `source_type IN (...)` 后 SUM |
| 设备多选入参 | 同理 `device_type IN (...)` |
| `registerToPlayRate` 等 | 现算；注册相关仅 `isNew=1` |

漏斗步骤建议返回有序数组，转化率用相邻步（或指定步）相除。
