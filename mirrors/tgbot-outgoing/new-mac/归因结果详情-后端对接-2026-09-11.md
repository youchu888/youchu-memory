## 1. 实际得分评估（结果表新列）

### 1.1 新列

| 列 | 类型 | 含义 |
|----|------|------|
| `score_brand` | INT | 品牌项**实际加分**（计算当时） |
| `score_model` | INT | 型号项实际加分 |
| `score_system` | INT | 系统名项实际加分 |
| `score_system_version` | INT | 系统版本项实际加分 |
| `score_time` | INT | 时间衰减项实际加分 |
| `time_bucket_max_seconds` | INT | 命中时间档（与 time_config.`max_seconds` 一致，如 600/3600/21600/86400） |

校验（成功行）：

```text
score = score_brand + score_model + score_system + score_system_version + score_time
```

**禁止**用当前 dim 配置反推历史分项；分项在打分时已落表。

### 1.2 产品详情查询示例

```sql
SELECT
    AVG(score_brand) AS avg_score_brand,
    AVG(score_model) AS avg_score_model,
    AVG(score_system) AS avg_score_system,
    AVG(score_system_version) AS avg_score_system_version,
    AVG(score) AS avg_score_total,
    SUM(CASE WHEN time_bucket_max_seconds = 600   THEN 1 ELSE 0 END) AS cnt_10m,
    SUM(CASE WHEN time_bucket_max_seconds = 3600  THEN 1 ELSE 0 END) AS cnt_1h,
    SUM(CASE WHEN time_bucket_max_seconds = 21600 THEN 1 ELSE 0 END) AS cnt_6h,
    SUM(CASE WHEN time_bucket_max_seconds = 86400 THEN 1 ELSE 0 END) AS cnt_24h,
    AVG(CASE WHEN time_bucket_max_seconds = 600   THEN score_time END) AS avg_time_10m,
    AVG(CASE WHEN time_bucket_max_seconds = 3600  THEN score_time END) AS avg_time_1h,
    AVG(CASE WHEN time_bucket_max_seconds = 21600 THEN score_time END) AS avg_time_6h,
    AVG(CASE WHEN time_bucket_max_seconds = 86400 THEN score_time END) AS avg_time_24h
FROM dws.dws_register_attribution_result_d
WHERE dt BETWEEN '${start_dt}' AND '${end_dt}'
  AND app_id = '${app_id}'
  AND attribution_status = 'success';
```

- 成功数 = 0：均值返回 `-`，档位次数 0  
- 渠道详情：加 `AND attributed_channel = ?`  
- 档位秒数若 app 自定义，建议 `GROUP BY time_bucket_max_seconds` 再映射文案，勿写死

### 1.3 样本明细（结果表已有列）

## 2. 无候选原因拆解（独立日表）

### 2.1 读哪张表

`ads.ads_register_attribution_no_candidate_reason_d_d`

| 列 | 说明 |
|----|------|
| `dt` | 注册业务日 |
| `app_id` | 产品 |
| `reason_code` | 原因码 |
| `reason_name` | 原因名称（与 code 固定映射） |
| `register_cnt` | 该原因下无候选入围注册数 |

**不要**用结果表 `unattributed_reason` 拼无候选（无候选多数不落结果表）。

### 2.2 原因码（PRD §7.2.1 顺序，互斥）

| reason_code | reason_name |
|-------------|-------------|
| `reg_ip_empty` | 注册IP为空 |
| `no_landing_same_ip` | 无同app同IP落地页 |
| `landing_channel_organic_or_empty` | 同IP落地页渠道均为空或organic |
| `time_not_met` | 非自然落地页不满足注册前24小时窗 |
| `uncategorized` | 未归类 |

前端直接展示接口返回的 code/name，勿自推文案。某原因为 0 时可不返回该行。

### 2.3 查询示例

```sql
SELECT
    reason_code,
    reason_name,
    SUM(register_cnt) AS register_cnt
FROM ads.ads_register_attribution_no_candidate_reason_d_d
WHERE dt BETWEEN '${start_dt}' AND '${end_dt}'
  AND app_id = '${app_id}'
GROUP BY reason_code, reason_name
ORDER BY register_cnt DESC;
```

### 2.4 与看板对账

同日同 `app_id`（board 跨渠道含 NULL 桶汇总）：

```text
SUM(no_candidate.register_cnt)
  = SUM(board.eligible_register_cnt) - SUM(board.has_candidate_cnt)
```
