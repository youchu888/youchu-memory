## 1. 星型模型是什么（Kimball → 本项目）

经典定义：中心一张**事实表**（存度量 + 维度外键），外圈若干**维度表**（存描述属性），查询时从事实表 JOIN 维度表做切片。

本项目在 Kimball 基础上做了几件事：

| 经典概念 | 本项目落地 |
|---------|-----------|
| 事实表 | `dwd` 原子事实 → `dwm` 轻汇总 → `dws`/`ads` 宽事实 |
| 维度表 | `dim.dim_user_all`、`dim.dim_date_info_all`、`dim.dim_user_daily_snapshot` 等 |
| 退化维 | 不建维表，直接写在事实行上（如 `title`、`content_type`） |
| 雪花模型 | **尽量不用**——维度属性优先 inline 或走统一 dim，避免多层 JOIN |

内容排行定案里有一句总纲：

> 作废「行星链路 dim→dwm→ads」；改为星型：中心是事实表，外圈仅挂**用户维 + 日历维**；内容 title/type 是事实行上的**退化维**，不建维表。

## 我掌握的核心（设计时会直接用）

**星型在本项目的定义：**
- 中心 = 宽事实表（`dws`/`ads`）
- 外圈 = 少量共享 dim（用户 / 日历 / 地区映射）
- 展示属性 = **退化维 inline**（不建 `dim_content_*` 这类维表）
- 衍生指标（rank/占比）= **查询层算，不落表**

**六原则（v3.3）：**
1. 事实优先 — 指标和 title 从 DWD 当天一次带出  
2. 单次扫描 — 每源每 biz_dt 至多扫 1 次，禁 dim→dwm→ads 双扫  
3. dim JOIN 克制 — 只 JOIN 真正需要的共享维，COMMENT 写清时点  
4. 度量分型 — cnt/amt 用 SUM；UV 用 bitmap；周月禁 SUM(日 UV)  
5. 策略 A — rank/prev_rank 查询双 CTE 现算  
6. 列卫生 — 不存恒 NULL / 废口径列  

**先判范式再动笔：**
