| `session` | `dws_session_duration_user_d` | 每个 session 墙钟分档 → 启动次数 |

| 字段 | session | daily |

| `session_cnt` | ✅ | NULL / 0 |
| `user_cnt` | ✅ | ✅ |
| `duration_sum_sec` | ✅ | ✅ |
| `avg_duration_sec` | ✅ | ✅ |
| `bounce_cnt` | ✅ | 可选 |

ETL 就是 **两段 SELECT `UNION ALL`** 写同一张表，不能一条 SQL 混算——上游聚合逻辑不一样。

## 要注意的点

1. **同名 `duration_bucket`，语义不同**  
   - session：单次墙钟落在哪档  
   - daily：当日累加总时长落在哪档  
   查询必须带 `stat_grain`，否则会把两种 Y 轴混在一起。

2. **PRD 两个看板仍是两个接口**  
   表合一了，前端/BI 还是要 `WHERE stat_grain='session'` 或 `'daily'`，各画各的柱状图。

3. **比 4→2 更省事**  
   设备不管 → 只动账号 2 表合 1，海豚 task 2→1，改动面比四表全并小。
